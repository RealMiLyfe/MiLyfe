## Cross-document authority

When documents overlap, use this order:

1. MiLyfe constitutional and authority rules
2. Security and safety rules
3. Approved architecture decisions
4. Versioned contracts
5. Roadmaps and release gates
6. Domain design documents
7. Agent prompts and task instructions

No agent may resolve a contradiction by silently guessing. The contradiction becomes an architecture decision or human-approval item.

## Transfer to the new GitHub repository

This design package should be transferred before product implementation begins.

Recommended sequence:

1. Create the new GitHub repository.
2. Add the repository root steering files based on documents `30` and `31`.
3. Copy this design package into `docs/design/`.
4. Add `AGENTS.md`, `SECURITY.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `LICENSE`, and `NOTICE`.
5. Configure protected branches, CODEOWNERS, issue templates, pull-request templates, security scanning, and environment protection.
6. Create the first bootstrap issue.
7. Have the first agent read this README and document `30` before doing any work.
8. Use document `31` for every subsequent implementation session.
